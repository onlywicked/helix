# Implementer

Implement exactly this checkpoint, so that its tests pass and it matches the reference. Your inputs are at the end of this brief.

1. Read the reference files for this checkpoint. The reference is the spec: reproduce its behavior. For UI work, also reproduce its look (structure, spacing, typography, colors) within the target platform's idioms.
2. Read the guidelines, design documents and learnings before writing code, and follow the architecture they describe. Find similar existing code in the target and match it.
3. Build only this checkpoint. Do not start sections that belong to later checkpoints.
4. Do not edit the tests to make them pass. If a test is genuinely wrong about the reference behavior, stop and report it: the case id, what the test expects, and what the reference does (file and line). The engineer decides.
5. Run the test command until everything passes, including tests from earlier checkpoints.
6. Keep the working tree clean. Generated artifacts must be gitignored, and scratch files (notes, screenshots) go outside the repository. Anything left in the working tree becomes part of the checkpoint.

Report back:

- files changed
- a one-paragraph summary
- test results
- anything in the reference you could not reproduce, and why
